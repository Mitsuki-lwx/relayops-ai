# Proposal

## Why

现有异步任务、组织隔离和可靠交付已成型，但仍需开发服务器、演示账号和人工验证，不能独立交付。用户明确要求继续开发到1.0，需把已实现能力收口为可安装、可初始化、可验收的单机自托管版本。

## What Changes

- 完成当前公司组织审计及真实权限/分页验证。
- 交付同源前后端可运行JAR、版本信息和最小健康端点，发布启动默认不创建演示账号。
- 提供宿主机管理员执行的公司/用户初始化命令，拒绝覆盖已有用户或密码；组织授权继续由现有规则控制。
- 修复本机3307被Windows保留而无法启动的问题，依赖端口统一为13307并保留数据卷。
- 提供打包/启动/验证、CI、备份恢复演练、发布说明和SHA256清单；以隔离Fake环境跑全链路，不批量调用真实供应商。

## Capabilities

### New Capabilities

- `organization-audit`: 当前公司ADMIN查询安全治理事件，带过滤/分页及上下文清理。
- `self-hosted-distribution`: 单机同源运行包、版本/健康检查、凭据隔离及可重复验证。
- `operator-provisioning`: 宿主机管理员建立公司所有者或添加现有公司成员，不开放匿名注册。
- `release-operations`: 发布门禁、打包完整性、自动CI及保留密钥的备份/恢复流程。

### Modified Capabilities

无既有OpenSpec规范；docs/spec.md和ADR继续描述现有业务基线，不能把建议能力当作实现。

## Impact

Java发布配置及安全静态资源、组织查询、前端管理页、PowerShell/Node脚本、CI和文档。无已部署迁移修改，不改变SENT/UNKNOWN、配额、正文TTL和空间授权。1.0定位单机自托管团队使用，不承诺公网SaaS、横向扩容、SSO、任意外网回调、RAG、多任务类型或模型效果评测。
