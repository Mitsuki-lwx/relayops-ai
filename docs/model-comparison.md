# 同供应商模型对照（2026-11-03）

## 范围
用户限定只对照同一供应商的 `qwen/qwen3.8-flash`。基线为 `cline-pass/deepseek-v4.1-flash-1017`，使用相同供应商兼容端点、相同提示词和固定评测集；没有引入第三家供应商或其他 Qwen 型号。

## 配置
| 项目 | deepseek | qwen |
| --- | --- | --- |
| 模型 | `cline-pass/deepseek-v4.1-flash-1017` | `qwen/qwen3.8-flash` |
| 供应商 | ClinePass compatible | ClinePass compatible |
| 超时 | 60秒 | 180秒 |
| 评审提示 | `review.compat.v2` | `review.compat.v2` |
| 版本提示 | `version.compat.v1`（对照时） | `version.compat.v1`（对照时） |
| 输出上限 | 8192 | 8192 |

qwen 首次以60秒运行评审时出现2/3超时，因此公平性对照使用180秒；这也说明其延迟显著更高。除模型与超时外，schema、prompt、预算、单次调用和评测规则相同。

## 观察
- qwen 需求评审有一个任务在180秒配置下仍超时；版本对比有一个任务 `OUTPUT_INVALID`（vd-003删除CSV）。
- 版本对比从v1的14/16提升到v2的16/16；v2明确忽略重排/格式/指令文本，qwen仅在v2单次通过。
- 但qwen版本对比仍只有单次运行，延迟27.79秒约为deepseek的4.9倍，Token也更高；不能据此宣称稳定性更好。
- qwen 的需求评审通过率、召回、延迟和 Token 均差于 deepseek；版本对比 v2 单次通过率与 deepseek 三次稳定基线的单次最好结果相当，但延迟约4.9倍、Token更高，且稳定性未测。
- qwen 的注入样本通过；不能据此推断其他安全能力。
- 超时配置不同是本次对照的混杂因素；若强制相同60秒，qwen 在评审上会更差。

## 结论
在当前固定样本和相同供应商下，**暂不把 qwen/qwen3.8-flash 作为默认或替代模型**：评审质量/延迟明显落后；版本对比 v2 有竞争力但只有单次运行。若后续要正式比较，应先为 qwen 增加至少三次重复、按模型固定超时，并分别记录超时/无效输出与语义错误。金额未知，Token 不是账单。
