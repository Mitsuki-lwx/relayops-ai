# RelayOps 任务执行与消息可靠性

状态：2026-10-30，用户已选择先完成最小纵向链路，边实现边解释原理。

当前增量：第八阶段增加受控本机结果交付。前七阶段功能保留，历史验证见 verification.md。

第三阶段：实现排队取消和失败／未知任务的明确重跑。Docker 迁移已完成，记录见 docker-storage.md。

## 背景与目标

RelayOps 为开发者异步处理技术文档，并可靠交付结构化结果。完整产品参考《RelayOps AI 任务平台完整设计文档》v1.0；当前阶段先建立登录、空间隔离、提交、持久化执行、结果查看的闭环，后续迭代再接入消息分发和可靠回调。

用户指定的 CLAUDE.md 决定工作流程；设计文档提供业务基线，其中代码示意、版本和尚不存在的工程包均不视为已实现事实。

## 用户

空间所有者和操作者可以提交任务并读取正文；观察者只能查看安全元数据。两个预置空间用于验证隔离。后台处理不依赖浏览器会话持续有效。

## 本阶段能力

- 登录、退出和查询当前用户的可访问空间。
- 服务端逐次检查空间成员和角色。
- 提交文本或 Markdown，并持久化任务及提交意图。
- 相同提交意图重放已有任务，冲突意图被拒绝。
- 按空间和受理日期限制调用额度。
- 后台通过默认假模型或显式配置的兼容接口生成带原文引用的结果。
- 保存前检查结果引用，原子提交结果与任务终态。
- 分别查询任务元数据和受授权的结果正文。
- 对执行结果不明的调用保留独立状态，禁止自动重新调用。
- 通过页面观察状态变化和结构化结果。

## 非功能要求

数据库是真实业务记录的来源。受理响应在事务提交后返回；网络或模型调用不占用数据库事务。正文加密保存并按保留期拒绝访问。日志不写正文、密码或密钥。角色隔离和幂等性要有负例验证。开发版明确标记假模型，不能声称已接入真实 AI 或完成全部可靠性设计。

## 设计骨架

采用 Java 模块化单体、Vue 工作台和真实 MySQL。第二阶段由事务 Outbox 记录待发布责任，RabbitMQ 分发就绪任务；消费者按数据库事实取得执行权。扫描器只恢复租约、过期任务和丢失的就绪责任，不直接调用模型。消息可重复，发送边界仍由状态、代次、执行租约和数据库唯一约束保护。可选择受控本机目的地，支持无目标仅查看。

## 第二阶段新增能力

- 创建任务与待分发消息在同一数据库事务提交。
- 发布器联合检查 Broker 确认与不可路由退回，确认未知时保留重发责任。
- 消费者处理完成并持久化后手动确认，重复消息不重复调用模型。
- 恢复时增加任务分发代次，旧消息和旧执行器不能覆盖新状态。
- Broker 暂停时有界受理，达到空间积压上限后拒绝新意图。
- 畸形、未知版本和关联不符的消息保存安全诊断，并进入隔离通道。
- 通过 Compose 自动下载与启动 RabbitMQ，持久化数据，凭据由本地配置提供。

## 本阶段不做

服务凭据管理、外网目的地、人工补投、完整监控、备份恢复、Redis、批量、多模型并发、PDF/OCR 和任意 URL 导入留给后续迭代。不生成空壳接口冒充支持。尚未提供独立工程文档包，因此不假造原设计所引用的 SQL、OpenAPI、完整验收 CSV 或评测样本。

## 第六阶段：taste前端重构

采用工作台设计规范重构应用外壳，主视图突出真实任务队列与可核对结果；新建文档、组织管理具有独立视图。提供本地标题/ID搜索和已载入任务的状态筛选，明确数据范围，不新增后端统计或伪造指标。

统一字体、字号、状态、表单、焦点与空状态。桌面采用双区任务/详情，平板折叠导航，手机可在列表与详情间返回。保留空间权限、外发确认、原键恢复、取消/重跑与组织授权的操作语义。

## 第七阶段：真实模型验收与结果完整展示

启用用户配置的兼容接口，以自拟短文通过真实任务链路验收。兼容标准结果及明确标为成功的网关包装结果；空工具字段不视为工具调用，实际工具请求仍拒绝。不执行工具，不自动重发。真实失败保留原记录和用量，修复后的复验使用明确的新关联任务。

结果展示覆盖摘要及其依据、关键结论、约束和未知项，空集合有明确说明。错误显示安全代码及用户可执行的说明，不展示供应商响应、密钥或内部异常。后续自动回归使用本机夹具/已完成任务只读校验，不批量调用真实供应商。

## 第四阶段：可配置的文档分析

用户选择 OpenAI 兼容接口。服务端可配置真实文档分析，默认保留免费开发模式。任务受理冻结配置标识，执行前检查仍有匹配配置；调用不自动重试。输出须通过结构和原文引用校验。长请求在执行权仍有效时续租，并受总调用时限约束；超时和不明确的供应商故障仍保留 UNKNOWN 责任。

工作台明确展示当前模式、配置和潜在费用，真实调用前由用户确认外发文档；密钥不进入浏览器、数据库结果或日志。该阶段用本机模拟供应商、真实数据库和消息链路验证，不代表已验证真实供应商效果或费用，也不新增组织权限能力。

## 第五阶段：公司、部门与小组

用户确认按空间共享，组织单元需显式授权。每个空间归属一家公司；公司成员可属于多个部门或小组，组织关系不自动授予任务访问。空间直接成员或显式授权的组织成员获得对应角色，多来源取最高权限；公司成员失效后所有入口拒绝。父部门不自动继承下属空间权限。

公司管理员管理部门/小组和已有公司成员的组织关系；同时拥有目标空间所有者权限才能配置组织到空间的授权。管理员身份不直接赋予正文权限。新建空间属于选定公司，创建者显式成为空间所有者。管理操作记录审计，撤销组织成员或授权后后续请求立即重查，已受理的后台执行继续履行责任。

旧空间分别归入独立公司，已有角色、任务、预算、加密上下文与消息保持有效。公司隔离覆盖身份空间列表、任务列表/详情/正文、预算/模型信息及命令重放。额度仍按空间；不提供公司注册、邀请新用户、公司计费、部门权限继承、仅本人可见或物理租户隔离。

## 第三阶段新增能力

- 当前空间操作者可取消尚未被领取的任务，释放其原受理日预留额度。
- 运行中和终态任务拒绝取消，取消与领取由数据库确定先后。
- 失败或结果未知的任务可明确重跑，用户说明原因并确认新的调用意图。
- 重跑创建关联到原任务的新任务，冻结当前配置并重新预留额度。
- 原任务与原已使用／不确定用量保留，不复活或自动退款。
- 命令校验当前权限、版本和幂等意图，重跑检查来源正文仍可用。
- 页面展示来源与新配置，网络确认丢失后恢复同一操作意图。

## 完成标准

干净数据库迁移成功；用户登录后提交文档并看到持久化结果；重复提交不重复占用额度；另一空间和低权限角色无法读取正文；执行结果不明时不自动重新调用；前端可构建，后端测试及真实数据库集成验证留有记录。未执行项目保持未勾选。

第二阶段还需真实 Broker 验证不可路由、重复消息、确认后数据库回写丢失、消费者确认丢失、Broker 暂停与恢复、旧代次、隔离和积压拒绝。不得用模拟 Broker 替代发布确认和消费确认测试。

第三阶段还需证明取消与领取竞争、跨日额度释放、来源历史保留、并发重跑去重、撤权/TTL 与预算/积压拒绝，以及浏览器命令响应丢失后的恢复。具体通过项和证据见 checklist.md 与 verification.md。

## 第八阶段：受控本机回调

所有者启停空间的受控目录目的地；操作者选定目标后，受理冻结目标快照。保存成功结果时原子建立独立交付责任。签名结果通过独立消息链路发送，自动退避重试、停用/过期终止、租约恢复和尝试时间线均不重新调用模型。观察者只读交付元数据；签名密钥仅所有者经显式审计读取。

本批仅本机独立演示接收端，不接收用户URL，不提供外网目录、密钥轮换或人工补投。旧任务不追补外发。完成标准是独立接收端的成功/故障/确认丢失能重复验证，正文与交付ID稳定，账目及调用次数不受回调重试影响。

## 第九阶段：单条补投

按原设计BR13增加两分钟预览与明确确认。仅当前操作者/所有者对最新DEAD交付发起，绑定当前版本、目标和载荷hash；确认重新检查权限、TTL、计划期限与目标状态。同一交付新建Run，历史保留，原字节和deliveryId不变，AI模型与用量不变。网络确认丢失可使用原幂等键恢复，刷新后不能自动发起新投递。外网目录、批量、成功交付补投及密钥轮换仍未实现。

## 第十阶段：到期在线载荷清理

七天TTL到期后分批清除在线输入、结果和回调密文并标记删除时间，保留所有业务责任元数据及审计。执行与恢复先结算活跃责任，未SENT不发调用，已SENT不重发；迟到结果不能重建已清正文。重复清理无副作用，未到期载荷不受影响。正文查询、重跑和补投均重查TTL及删除状态；备份、底层页、日志、接收端文件和三十天元数据清理不属本批。
