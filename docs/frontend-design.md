# RelayOps taste app redesign

2026-10-30。使用本机taste skill的app-screens流程。draw抽到framed-sheet与achromatic-ledger，选择framed-sheet，seed 1361095215，无重抽；开发者长时间处理队列适合固定外壳和白色工作面。

数据盘点：
- Job来自现有API，含标题、状态、日期、版本、来源与调用记录；每次最多载入50条，不冒充全部历史。
- 状态为排队、运行、成功、失败、未知、取消；需关注仅由已载入的失败/未知任务计算。
- 每空间每日20次默认额度，实际值以服务端budget为准；预留、使用和不确定不互相重复计入。
- 模型名和是否可能收费来自profile；提交与重跑确认保留。
- 结果、引用和到期时间来自受授权查询；未读取时不预填摘要。
- 公司、部门、小组、角色与授权来自真实组织接口；组织治理独立为一个视图。
- 操作者的主任务是提交文档后定位结果；观察者只能查看元数据。
- 登录、创建、取消、重跑、读取、组授权和响应丢失恢复均保留原API语义。

主问题：哪些任务需要处理，选中的任务有什么可核对的结果？主视图是任务队列和详情，新建文档与组织管理各自独立视图。数据保持真实，无演示数字或假图表。

产品特征：RelayOps的relay语义成为双节点连接标记；任务状态链（受理→处理→验证结果）成为详情的真实状态标记；IBM Plex Sans配合中文系统字族，ID使用等宽字体。浅青灰外框、白色工作面、228px侧栏、48px顶栏、24px统一间距，数据状态和实际额度条承载颜色。

桌面1440：228px侧栏 + 8px外缘 + 2px工作面边框 + 48px内距 + 1154px内容；任务区域为750px列表 +24px间隔 +380px详情。平板侧栏折叠为导航；手机一次显示列表或详情，返回保留筛选，新建表单和组织表单单列。

验收：构建与真实浏览器；taste lint与inspect；1440/768/390实拍、键盘与减少动态偏好。验收使用Fake后端，不发送真实文档到模型供应商。

组织视图的主问题：哪些部门/小组及成员已获得空间访问？桌面将现有成员与授权放在右侧，表单在左；窄屏先显示限高可滚动的现有授权，再显示管理表单。编辑视图的主问题：此次提交的范围、额度及输入是否正确？表单旁展示真实空间、角色与保留期。

自审：队列是最大工作区，详情中的状态链和原文入口紧邻任务；表单与现有权限分区，不拉伸短详情制造空白。额度、预留/使用/不确定均来自同一budget；状态计数由同一已载入Job数组计算，过滤结果说明范围。真实零值保留0，无缺失统计占位和虚构趋势。无图表，因此无图例/曲线。手机导航折叠，详情可返回；字号最小11px仅用于开发标记，辅助文字13px，焦点与减少动态偏好均验证。

检查说明：taste lint的3条mono警告保留，因为app-screens明确允许真实ID/Key使用等宽字，3处分别是字体声明、Job ID与Profile ID。任务/编辑/组织原生inspect最终均0FAIL/0WARN；仅对本地DOM快照做测量，动态/API操作用真实浏览器回归。静态快照嵌入同一字体，避免临时检查服务器的路径差异；不保存会话或密码。没有需要替换的虚构示例数据，截图中的账号和任务是本机验收记录。
