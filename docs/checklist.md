# 首阶段验收

未执行或证据不足的项目保持未勾选。完整设计中的 80 条验收用例尚未提供独立工程包，以下为本阶段新增验收。

## 构建与持久化

- [x] JDK 21 执行 `mvn test` 通过（15 项，包含 7 项真实数据库集成测试）。
- [x] `npm ci`、`npm run build` 通过，保留 lockfile。
- [x] 在 MySQL 8.4 执行迁移，再启动不重复初始化账号或空间。
- [x] 202 响应包含 jobId、QUEUED、到期时间；数据库中已存在对应任务与额度分录。

## 登录与授权

- [x] 未登录查询任务返回 401；登录缺少 CSRF 返回 403。
- [x] 登录后重新获取 CSRF；退出后旧会话无法访问工作台。
- [x] 空间 A 用户请求空间 B 任务返回 404（已验证等价的 B 用户请求 A 任务）。
- [x] VIEWER 可见元数据，提交或读取正文返回 403。
- [x] 成员撤权后再次读取或重放旧幂等键被拒绝。

## 任务与调用边界

- [x] 输入 NFC 规范化、换行转 LF；6000 Unicode 字符或 24576 UTF-8 字节为上限，NUL/空文本拒绝。
- [x] 同主体、空间、操作、幂等键及请求只产生同一个 Job；不同请求返回 409。
- [x] 默认空间额度为 20；隔离空间设置额度 2，4 个并发意图只有 2 个受理，另外 2 个返回 429。
- [ ] 在默认额度 20 的独立空间实际提交 21 个意图，验证第 21 个返回 429（本次使用等价的小额度竞争测试）。
- [x] 每个 Job 最多一次 SENT；重复恢复扫描不增加 Fake 调用次数。
- [x] 调用结束验证结果结构和 evidence 的 paragraphId、quote，成功 Job 只有一个 Result。
- [x] SENT 后租约失效进入 UNKNOWN，额度转 UNCERTAIN，不自动重调（数据库故障状态注入，未做真实进程 kill 演练）。
- [x] 正文使用外置 32 字节密钥的 AES-GCM；存储入口只写输入和结果密文。
- [x] 正文到期后读取返回 410，即使物理密文仍存在（测试直接推进数据库到期时间，未等待实际七天）。

## 接入与端到端

- [x] 浏览器登录→默认空间应用→提交文本→轮询→看到结果和原文依据；接口验收另核对 QUEUED 受理响应。
- [ ] 详情每 5 秒轮询，页面隐藏暂停，终态停止；恢复可见立即刷新。
- [x] 网络响应丢失后用原幂等键重试原请求，重载页面仍能查询结果。
- [x] 390px 宽可完成登录、提交和结果阅读，提交按钮支持键盘 Enter；全程纯键盘导航仍待专项检查。
- [x] `node scripts/smoke.mjs` 在真实 MySQL 服务上通过，并保存实际记录。

## 后续边界

- [x] RabbitMQ/Outbox 与分发故障恢复已按第二阶段专项验收；回调尚未实现，当前不宣称完成完整 P0。

## 第二阶段 Outbox 与 RabbitMQ

- [x] Compose 自动拉取并启动 RabbitMQ，5672/15672 只绑定 127.0.0.1，随机凭据保存在忽略的 .env。
- [x] V2 迁移追加分发代次、Outbox 与隔离诊断；已有 QUEUED 任务获得首条 Outbox，V1 不变（专用库实际 V1→V2 用例和文件哈希）。
- [x] 受理事务失败时没有孤立 Outbox、Job 或预算占用；同键并发只产生一条首代 Outbox。
- [x] 就绪消息只含八个允许字段，没有输入正文、结果、URL 或凭据。
- [x] 未绑定 routing key 收到 mandatory return 后仍可重试，不错误标 SENT。
- [x] Broker 已确认但刻意省略 Outbox 回写，租约恢复后重发同 messageId，模型只调用一次；过期发布者更新被拒绝。
- [x] 同一信封重复十次、结果提交后关闭 channel 丢失 ACK 再投递，仍只有一个 SENT 和 Result。
- [x] PREPARED 租约过期后新代次重排；旧代次消息不执行，旧 token 无法结算。
- [x] SENT 租约过期转 UNKNOWN/UNCERTAIN，重复恢复与旧消息不再次调用。
- [x] 已发布超过 120 秒未领取的 QUEUED 任务生成新代次；重复扫描不为同代创建多个 Outbox（测试推进数据库时钟字段）。
- [x] 非法 JSON、未知版本、错空间和不存在关联写安全诊断；原始消息拒绝，隔离队列只收到 hash/错误码通知，DB 和通知均无原始秘密正文。
- [x] Broker 实际停止期间已受理任务保持 QUEUED；恢复后完成。独立积压上限 2 的集成用例验证第三个新意图返回 503，不增加额度占用。
- [x] 注入数据库异常时没有 ACK，关闭实际 channel 后消息重入队；容器设置五秒恢复间隔，Broker 停止时实际日志显示间隔重连。未演练真实 MySQL 停机。
- [x] 27 项后端测试、原有 HTTP 冒烟、真实 Broker 停启和 3 项浏览器回归通过，保留日志。

## 第三阶段取消与明确重跑

- [x] V3 保留旧 Job，并补齐旧 CREATE_JOB 成功响应；V1/V2 哈希不变。
- [x] QUEUED 取消变 CANCELLED，原受理日分录 RELEASED，reserved 只减一次。
- [x] RUNNING 和终态取消返回 409，不退款或重复改状态。
- [x] 取消与领取竞争只有“取消成功且零 SENT”或“取消 409 且最多一次调用”。
- [x] 取消后的旧 MQ 信封不创建 Attempt、不调用模型。
- [x] FAILED/UNKNOWN 重跑产生新 ID、parentJobId 和 Outbox，来源终态与用量不变。
- [x] 新任务使用当前 fake-extract-v1 配置，输入独立加密且能按新上下文解密。
- [x] 缺风险确认、空原因或原因超过 300 字返回 422；来源过期返回 410。
- [x] 缺版本/键拒绝，旧版本或同键改资源/原因/版本返回 409。
- [x] 同键并发重跑只产生一个新 Job 和一次预留，重放响应不变。
- [x] VIEWER 403、跨空间或撤权后的重放 404，无新增业务副作用。
- [x] 预算或积压拒绝后无子 Job、幂等成功记录或新 Outbox。
- [x] 浏览器能取消、明确重跑、跳转新任务并查看来源。
- [x] 命令响应丢失后刷新沿用原键，不重复释放或占用额度。
- [x] 390px 和键盘可完成命令，错误、冲突与过期状态可见。

## 第四阶段兼容模型

- [x] 默认 Fake；兼容配置无效时启动失败，信息不含密钥。
- [x] 请求携带正确 Bearer/模型/JSON/段落编号，响应的元数据由服务端决定。
- [x] 完整响应体超时、断连、非明确拒绝的状态不自动调用第二次。
- [x] 400/401/429 拒绝、拒答、截断、非法 JSON 和伪造证据不保存成功结果。
- [x] 响应超过 128 KiB 拒绝；重定向不跟随；慢响应体也受总时限约束。
- [x] 配置不匹配的旧任务在 SENT 前失败；旧 Fake 任务可继续处理。
- [x] 受理与明确重跑保存当前配置，不修改来源任务。
- [x] 长请求续租后仍只产生一条 SENT/Result；旧 token、过期租约和旧代次不续期。
- [x] 工作台显示模式与模型；可能外发/收费的首次提交需要明确确认；密钥不进浏览器。
- [x] 后端隔离测试和浏览器验证通过，V1/V2/V3 校验不变，提交推送后远程与本地一致。
