# AI 任务使用事务 Outbox 与 RabbitMQ

日期：2026-10-29。第二阶段决策，替代 ADR 0001 中的数据库直接扫描执行方式。API、配额和模型发送边界保持原有语义。

任务受理事务同时写入 Job、预算分录、幂等映射、审计和唯一 Outbox。发布器只锁定到期 Outbox，提交发布租约后在事务外发送。持久化消息、publisher confirm ACK 和无 mandatory return 同时成立才标 SENT。确认或数据库回写丢失允许重复发送同一 messageId。

AI 队列采用单节点 durable classic queue，消费者并发和 prefetch 均为一，手动 ACK。消费者从数据库重新校验 messageId、空间、任务和代次，领取成功后才创建 PREPARED。SENT 已发生的任务绝不再次调用。业务失败、UNKNOWN 与成功都以数据库记录为准，不通过无限 requeue 重新执行模型。

Outbox 发布每批最多五十条，整批等待确认的总预算五秒；租约三十秒。失败指数退避到最多三十秒并加抖动。连接失败后不对批内每条重复阻塞建连。超过单次调用预算时保留可恢复责任，不删除消息。

恢复未 SENT 的过期执行权时终止旧 PREPARED，递增代次并在同一事务写新 Outbox。已 SENT 的过期执行权标 UNKNOWN 并把额度转 UNCERTAIN。已发布超过一百二十秒仍 QUEUED 的任务可递增代次重建消息。旧消息和旧 token 只能被忽略，不能覆盖当前执行。

每空间未发布 Outbox 默认上限一千；受理在预算锁内检查容量，超过上限返回 503。数据库集成测试使用小额度和小积压上限验证边界，MQ 故障测试使用独立数据库和 vhost，避免干扰工作台演示记录。

诊断持久化只保存消息哈希、允许格式的 messageId 和固定错误码，不保存不可信原文。与设计文档示意的 DLX 转发相比，本实现拒绝原始消息前先保存 DB 诊断，再向隔离交换机发送仅含 hash/错误码的安全通知；不把原始不可信字节转入 DLQ，避免潜在 secret 再次被保存。隔离队列通知为尽力发送，DB 诊断是运维依据。诊断入库失败或业务数据库异常时不确认消息，通过关闭消费 channel 与五秒恢复间隔避免热循环。

继续使用短时确定性假模型，无真实供应商调用。租约续租、真实模型超时、交付消费者和端到端恰好一次不在本次范围。
