# 0010 完整任务历史与服务端筛选

2026-10-31，已实现并验证。原设计规定按created_at DESC/id DESC列出任务，UUID不代表提交顺序。本批新增独立历史入口，保留最近50条队列及其本地筛选，避免将局部数量误作全量。

GET /api/v1/workspaces/{id}/job-history面向当前所有有效空间成员，只返回既有Job元数据DTO，SQL显式选择安全列，不读取输入密文。使用只读RR事务，当前空间授权先于筛选校验，每页默认25、范围1–100。无新增迁移或任务执行/预算/审计写入。

可选q为trim/NFC后的标题或任务ID字面子串，最多100个Unicode码点，空白表示无搜索；使用LOCATE及绑定参数，不将%/_/反斜线解释为通配符。大小写/重音遵循现有MySQL表排序规则，不搜索正文、模型响应或其他空间。status接受ACTIVE（QUEUED/RUNNING）、ATTENTION（FAILED/UNKNOWN）及六个精确Job状态，缺省全部，其他值422。

响应items及可空nextCursor={createdAt,id}；cursor取本页最后一条，查询下一页需同时传beforeCreatedAt/beforeId。时间必须可解析为UTC Instant、毫秒精度且MySQL支持的年份1000–9999；ID必须为规范UUID。不查询游标所属任务，不因删除/跨空间游标泄漏其他空间存在性；游标只作本空间排序截点。查询limit+1判断有无更早页，使用(created_at < time OR created_at = time AND id < id)确定次序，时间相同以ID消除重复。

分页是可变业务状态的浏览，不是跨请求数据库快照或消费协议。新任务不会推挤当前游标导致重复，但晚提交的旧时间记录和状态变更可改变后续页；刷新首屏重新查询。原始元数据保留不受正文TTL影响，历史可见不代表仍可读正文。

页面沿用taste framed-sheet，由任务队列底部进入、可返回队列；手动查询和翻页，不新增轮询。输入改变须提交，下一页绑定已应用筛选；显示当前应用条件，防止草稿与结果混淆。切空间、卸载、失败拒绝均清除结果和游标，AbortController与上下文序号丢弃迟到响应。点击历史行进入现有详情并重新读取当前授权元数据，正文仍须显式读取；不自动调用模型。

不新增全文检索引擎、导出、全量下载、跨公司列表、页码总数、无限增长缓存、日期/应用高级筛选或生产性能结论。
