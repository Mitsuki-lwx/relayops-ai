# 首阶段使用数据库扫描与假模型

日期：2026-10-29。状态：按用户选择的最小纵向链路实施。

完整设计采用 RabbitMQ 和 Outbox。首阶段先验证身份、任务事务和持久化结果，因此用单个数据库扫描执行器领取 QUEUED 任务；消息层在下一迭代接入。返回 202 表示数据库已承接责任，不代表处理完成。

不在事务中执行模型：先领取并持久化 PREPARED，再提交 SENT 和配额消费，然后调用假模型，最后用租约条件提交结果。SENT 是本平台不能自动重试调用的边界；进程即使在 SENT 后尚未真正发送，也保守进入 UNKNOWN。

假模型仅摘录输入段落来构造确定性 evidence，不代表语义理解或真实模型质量。没有外部收费调用。此阶段不启动真实模型适配器。启动只允许 local 配置；完整生产安全、保留清理和运行治理不在本阶段发布承诺内。
