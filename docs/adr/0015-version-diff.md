# ADR 0015：文档版本对比与影响分析

## 状态
已接受（2026-11-03）。

## 背景
团队需要在两个版本之间确认语义变化及其影响的约束和验收项。直接比较模型摘要会丢失原文依据，也会把“摘要相同”误当成“没有变化”。

## 决策
- 新增 `VERSION_DIFF` 用途和结果版本 `version.diff.result.v1`。请求使用 `inputText`（基线）和可选 `inputTextB`（修订）；仅该用途要求第二份文本。
- 不新增数据库列：两份文本分别用现有 `DocumentInput.normalize` 校验后，组合存入现有 `input_cipher`。段落 ID 分别使用 `a0001`/`b0001` 前缀；原文若包含内部标记直接拒绝。
- 结果为可选 `diff`：最多8项 `ADDED/REMOVED/MODIFIED` 变化、最多6项受影响约束和最多6项受影响验收草稿。新增只引用修订、删除只引用基线、修改必须双侧引用；引用仍按段落ID和原文子串精确校验。
- 独立提示词/profile `version.compat.v1`，复用评审输出上限8192；不改变 EXTRACT/REQUIREMENTS_REVIEW 的提示词、profile、幂等指纹或结果格式。
- 重跑按来源 `schema_version` 恢复用途，从组合输入拆出两份文本；读取结果和 Worker 按 schema 选择段落解析。旧任务兼容。
- 前端双文本框、用途/配置切换、待确认草稿、结果视图和Markdown报告；不自动合并、不修改需求、不执行测试。回调外壳仍为 `relay.webhook.v1`，以 `result.schemaVersion` 区分。
- 首版不新增版本存储、差异编辑器、跨文档检索或自动变更建议采纳。

## 后果
- 组合输入是内部格式；标记冲突会被拒绝而不是静默转义。单份文本上限仍为6000字符，两份都受约束。
- 语义变化和影响分析可能漏报或误报，界面/报告必须标注待人工确认。
- 真实模型样本、Langfuse、回调与报告需独立验收；固定评测集暂不包含版本对比。
